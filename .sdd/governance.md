# Governance

> How this repository's SDD conventions themselves are versioned and
> changed. See `manifest.yaml` for the machine-readable version this
> repository currently follows, and `constitution.md` for the engineering
> principles this governance model enforces.

## Current governance version

See `manifest.yaml` → `governance_version`.

## Changing governance

When these conventions change (e.g. a new artifact type becomes
recommended, or a gate's requirements change):

1. State the new version number.
2. State what's **required** for repositories/units moving to the new
   version.
3. State what's explicitly **not required** — existing historical artifacts
   should not need retroactive rewriting just to comply, unless the change
   is safety- or correctness-critical.
4. Note backward compatibility explicitly.
