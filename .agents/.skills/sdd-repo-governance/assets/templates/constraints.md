# Standing Constraints

> Constraints that apply across the project and shouldn't need to be
> restated in every spec. Unit-specific constraints still belong in that
> unit's `spec.md` under its own "Constraints" section.

## Business constraints

[e.g., regulatory requirements, budget/timeline constraints, contractual
obligations]

## Technical constraints

[e.g., must integrate with an existing system, must run in a specific
environment — kept technology-agnostic where possible, per the SDD

[e.g., team size, available skill sets, compliance/approval processes]
